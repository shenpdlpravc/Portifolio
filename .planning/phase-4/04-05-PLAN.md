# Plan 05: Navegação e Visibilidade na Página Não Encontrada

## Objetivo
Garantir que a navbar funcione universalmente em qualquer subpágina ou tela de erro (404) e que os botões (Github, LinkedIn, Theme) mantenham sua visibilidade mesmo que os estilos padrão do Next.js sejam sobrescritos.

## Contexto
Durante a verificação da Fase 4, foi descoberto que ao clicar no botão "Currículo" (que aponta para `/curriculo.pdf`, um arquivo que ainda não existe, gerando uma tela 404):
1. Os links de âncora da Navbar ("Sobre", "Projetos", "Contato") param de funcionar, pois estão formatados de forma relativa (`#sobre` procura o elemento na própria página de erro em vez da home).
2. O botão de toggle de tema e os ícones de redes sociais ficam invisíveis no Light Mode porque a tela padrão de erro do Next.js afeta as cores base herdadas.

## Passos de Implementação

1. **Atualizar `src/app/layout.tsx`**
   - Adicionar a classe utilitária `text-foreground` explicitamente ao `<body>`.
   - Localizar: `<body className={`${inter.className} min-h-screen bg-background font-sans antialiased flex flex-col`}>`
   - Alterar para: `<body className={`${inter.className} min-h-screen bg-background text-foreground font-sans antialiased flex flex-col`}>`

2. **Atualizar Âncoras Absolutas**
   - Em `src/components/navbar.tsx`, alterar:
     - `href="#sobre"` para `href="/#sobre"`
     - `href="#projetos"` para `href="/#projetos"`
     - `href="#contato"` para `href="/#contato"`
   - Em `src/components/mobile-menu.tsx`, replicar a mesma alteração para os links do menu móvel:
     - `href="#sobre"` para `href="/#sobre"`, etc.

## Verification
- Clicar em "Currículo" abrirá o 404, porém os ícones continuarão visíveis no Light Theme.
- Ao clicar em "Sobre", "Projetos" ou "Contato" na tela de 404, a aplicação deve navegar de volta para a Home e realizar o rolamento correto.
